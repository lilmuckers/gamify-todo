# CLAUDE.md

Guidance for Claude (and other agents) working in this repo. The full product spec is in
[`SPEC.md`](SPEC.md): read it before changing behaviour. User-facing docs are in
[`README.md`](README.md), the data format is in [`schema/README.md`](schema/README.md), and the
LLM data skill is in [`skills/quest-log/SKILL.md`](skills/quest-log/SKILL.md).

## What this is

**Quest Log** (repo `lilmuckers/gamify-todo`; site `https://tasks.patrick-mckinley.com`) is an
anti-perfectionism project tracker drawn as a retro Mario-style platformer. The tree is
project → world → level → items. A level is one deliverable with a time-box and success
criteria, and it clears when its MVP criteria are ticked. All state is JSON under `data/` in a
GitHub repo: this one, or any repo the user picks in Settings.

**FiftyPIFS** ("fifty penguins in fuzzy socks") is the owner's company. Its logo (a pixel penguin
in fuzzy socks) and wordmark make up the boot splash in `app/index.html`. The app itself is
Quest Log.

## Commands

```bash
npm install
npm run dev                     # Pages-mode app, http://localhost:5173
npm run dev:server              # Docker-editor API on :8787 against THIS checkout (it commits here!)
VITE_TARGET=local npm run dev   # local-editor front end, proxies /api to :8787
npm test                        # vitest: shared/test, app/test, server/test
npm run typecheck               # tsc for shared, app, server, e2e
npm run e2e                     # Playwright: builds both targets, drives them in Chromium (e2e/README.md)
npm run validate                # schema + semantic validation of data/
npm run format:data             # canonical formatting of data/ (CI only warns)
npm run schema:gen              # regenerate types.gen.ts + validators.gen.js after editing schema/
npm run skill:version           # bump the skill version after editing SKILL.md or quest.py
npm run build:pages | build:local
docker compose up --build       # local editor at http://localhost:8080
cd worker && npx wrangler@4 deploy --env="" --var GITHUB_CLIENT_ID:…   # sign-in Worker (worker/README.md)
```

`.claude/launch.json` defines `app-pages` (5173), `server` (8787), `app-local` (5174) and
`app-preview` (4173). To try Sign in with GitHub locally, run `worker` (`wrangler dev --env dev`
on 8788, secrets from `worker/.dev.vars`) with `app-signin` (5173, pointed at that Worker with
the real App's Client ID and slug). The App's callback URLs must include `http://localhost:5173/`.

**Before pushing**, run `npm run typecheck`, `npm test` and `npm run validate`, plus
`npm run e2e` if you changed a flow it covers (scenes, panels, pads, sync). If you touched
`schema/`, also run `npm run schema:check`. If you touched `skills/quest-log/SKILL.md` or
`quest.py`, run `npm run skill:version` (CI runs `skill:check`, which fails without the bump). CI (`.github/workflows/validate.yml`) runs all of
these on every PR. `pages.yml` deploys `main` to GitHub Pages.

## Architecture rules that matter

- **Every edit is an op.** Add a new op kind to `ProjectOpBody`/`OpBody` in `shared/src/ops.ts`.
  Handle it in `applyLevelOp`/`applyProjectOp`/`applyOp`, `describeOp` (commit text) and, if
  it's undoable, in `inverseOp` + `UNDOABLE`. Then cover it in `shared/test/ops.test.ts` and
  `structural.test.ts`. Never write files directly from UI code.
- **Copy-on-write.** `applyProjectOp` copies only the overworld, world or level it writes to. It
  must never mutate its input (the tests deep-freeze it). Views, `revalidate` and `changedFiles`
  rely on reference identity to skip unchanged projects.
- **Store** (`app/src/data/store.ts`): ops are applied optimistically and queued in an IndexedDB
  outbox. Sync loads remote, replays the outbox on top, validates and commits the changed files
  once. On `ConflictError` it reloads and retries (max 3). Ops whose target is gone become
  conflicts and are listed in Settings → Sync. `retract()` takes back an unsynced op with no
  commit and no polish. `hold()`/`release()` is used by play mode.
- **DataSource** (`app/src/data/source.ts`): `StaticSource` (read-only Pages), `GitHubSource`
  (token, atomic commits via Git Data API), `LocalApiSource` (Docker `/api`), `DemoSource`
  (in-memory; `?demo`). Capabilities (`canEdit`, `canReviewPRs`, `canPublish`) gate the UI.
- **`shared/` stays pure.** No DOM, Phaser or Node-only APIs, because the browser and server
  both use it. Play physics (`app/src/game/play/physics.ts`) and other logic you want tested go
  in Phaser-free modules.
- **Level scene renders in layers** (scenery / goal / items), each redrawn only when its inputs
  change. Item views are keyed by item + x. Don't rebuild the whole stage on every change: it
  restarts every tween and was a deliberate perf fix (#72).
- **Render loop** emits `'all'` or `'sync'`. A sync-only emit repaints only the HUD pill and
  panel footer. Fields marked `data-keep` survive re-renders while focused.
- **Catch-up** (`app/src/game/catch-up.ts`): when a hidden/throttled tab comes back, one-off
  tweens, timers and camera effects run to their end. Build animations as promise chains on
  `QuestScene.tween()`/`wait()` so they work with this.
- **Reduced motion** is honoured everywhere: no jumps or bends, and the end state is shown at
  once.
- **Schema changes** need updates in five places: `schema/quest.schema.json` (with descriptions
  on every field and enum value, because LLMs learn the format from them), `npm run schema:gen`,
  `skills/quest-log/SKILL.md`, `schema/README.md` and `skills/quest-log/scripts/quest.py`. Parity
  tests (`shared/test/skill*.test.ts`) keep quest.py and the SKILL examples in step with the
  TS validator. Then `npm run skill:version`, so assistants with an older copy reload the skill.
- **The skill's three standing rules** (top of SKILL.md) are: check `version.json` for a newer
  skill first, validate the whole tree before anything is committed or handed over, and update
  from the base branch before opening or adding to a PR. Keep them when editing the skill.
- **Security.** The Pages build has a strict CSP (`app/vite.config.ts` `csp()`): connect only to
  self + `api.github.com` (+ GA). The token lives in `localStorage` and is only sent to
  `api.github.com`. The server listens on loopback, checks `Host` (`ALLOWED_HOSTS`), requires
  `X-Quest-Client: 1` plus a same-origin `Origin` on writes, and only writes `data/` paths.
- **Analytics** (`app/src/analytics.ts`): every event parameter goes through an allow-list.
  Never send titles, ids, notes, repo names, logins or tokens. Page views use the screen type,
  never the URL. A new event needs an allow-list entry and a test.

## Conventions

- TypeScript, ES modules, 2-space indent, single quotes, no UI framework (`h()` from
  `app/src/ui/dom.ts`).
- Comments are short JSDoc on exports and explain *why*. Match the existing density.
- British English in UI copy and docs ("colour", "behaviour"). The tone is playful but plain,
  with short sentences.
- Commit subjects are imperative, plain English, with no conventional-commit prefix ("Catch
  animations up after a hidden or throttled tab"). The body explains the problem, then the fix,
  often with bullets and measurements. Reference issues with `Fixes #n` / `Closes #n`.
- Commits the app makes to data look like `quest: done: <title> (<project>/<world>/<level>)` or
  `quest: N updates`. **Don't commit stray `data/` edits** made while testing the app locally.
  They have been reverted before ("Revert stray app data edits", "quest: settings: hero = goth").
- Art is original pixel art drawn in code from the palette in `sprites/pixels.ts`. No Nintendo
  assets, and no external images.
- **Adding a hero** touches the schema, `HERO_IDS`, 16×16 sprites, 32×32 portraits, a 48×64
  fighter look, a bio and quote, 18 tour lines and 73+ easter-egg lines in that hero's own voice. Follow the full guide and checklist in
  `SPEC.md` §18. Voices come from style and personality, never from background, identity or
  accent. Tests fail until every piece is there.
- Ids are lowercase kebab-case and never renamed. Folder and file names equal ids. `world` is a
  reserved level id.
- Mobile: the compact DOM UI is used under 768px wide or on short touch screens. Text fields are
  ≥16px on touch (no iOS zoom), safe-area insets are respected, and phones have no play mode.

## Gotchas

- `npm run dev:server` and the Docker editor **commit to the checkout they run in**.
- GitHub's branch ref can lag right after a commit. The GitHub source keeps the newer head if the
  loaded one is its ancestor.
- An empty GitHub repo is detected via `GET /commits?per_page=1` → 409, not via `size`.
- The Docker build serves live data through `/api`. Demo example data ships under
  `examples/data/` there, and under `data/` on Pages.
- `stats` on a level is app-maintained. Tools writing data must not touch it, but should set or
  remove `doneAt` when they change status.
- Play-mode edits are held and not synced until the end-of-play summary is confirmed. Held edits
  persist across reloads.
